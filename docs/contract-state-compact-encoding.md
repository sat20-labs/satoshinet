# 合约状态紧凑编码

实施日期：2026-10-11。范围：模板、EVM、Agent 的运行状态及节点保存的合约快照。功能未上线，按用户批准直接替换格式，不读取旧 JSON 快照或旧 EVM 内嵌 JSON 余额，不提供迁移或兼容分支。

## 保存路径与格式

| 数据 | 原保存方式 | 新保存方式 | 入口 |
| --- | --- | --- | --- |
| 模板运行状态 | JSON | `TRS` + 版本 1，固定字段二进制 | `contract/template/compact_state.go`、`saveRuntimeState` |
| 模板 RuntimeStore 快照 | JSON，内层 JSON 作为字节字段再次编码 | `TSS` + 版本 1，固定字段二进制，内层状态原始字节 | `contract/template/state_codec.go` |
| Agent RuntimeStore 快照 | JSON，恢复时经过 JSON 状态桥接 | `ASS` + 版本 1，固定字段二进制，直接恢复类型化状态 | `contract/agent/state_codec.go`、`compact_state.go` |
| EVM MemoryStateDB | EVMSTATE V1 二进制，ManagedBalance 内嵌 JSON | EVMSTATE 二进制（沿用原格式标识 1），ManagedBalance 也为二进制 | `contract/evm/state_codec.go` |
| 三类 ManagedBalance | JSON | `MB` + 版本 1，固定字段二进制 | `contract/state_binary.go` |

节点的 `TemplateStateStore`、`AgentStateStore`、`EVMStateStore` 仍通过原有数据库事务和 tip/block 键保存上述快照；没有增加数据库、索引、后台任务或持久化状态。

共享编解码工具只处理基础字段，不使用反射、gob 或类型注册。整数字段采用变长无符号整数，有符号整数采用 zigzag；字符串和字节数组采用长度前缀；Decimal 保存 nil/符号、精度和整数绝对值。map 按键排序，ManagedBalance 按资产三元组排序并清理零资产，切片保留原顺序。

解码校验格式头、版本、字段范围、Decimal 范围、长度、重复或无序 map 键以及尾随字节。集合分配前按剩余字节与记录最小长度检查容量，不新增业务容量限制。ManagedBalance 保留金额、精度、绑定参数及重复资产校验。InvokeItem 保留旧 JSON 读取时的金额规范化和 Param/OrderType 一致性校验。

编码 schema 的字段顺序在模板及 Agent 的 `compact_state.go` 中明确写出。增加或调整持久化字段时，必须同时修改对应读写函数和往返回归；不能只增加结构体字段。功能未发布，不为本轮编码调整新增 V2 或兼容路径。

## 状态根

按本轮用户要求，模板、Agent 不再生成临时 JSON，直接复用固定字段 `writeXXX` 编码写入 SHA256。编码同时服务持久化与哈希，map 排序、长度前缀及切片顺序均具有确定性；不使用 gob。

- 模板：地址、模板名、模板版本、部署者、nonce、部署 flags、合约内容、ManagedBalance、当前高度、调用次数参与根计算；随后直接写入 NextItemID、InvokeCount、未完成 item 数量及记录，以及当前模板的运行字段。flags 与 ManagedBalance 已补入 RuntimeStore 实际调用的 `ContractRuntime.StateRoot()`，使用与 RuntimeBase 相同的字段顺序；正常解码及原有解码失败回退路径均包含这两个字段。已完成 item 和其他模板的运行分支仍不参与该模板根。`templateCanonicalStatePayload`、根 payload 结构和 `unfinishedItems` 已移除；对 item 先计数、再遍历写入，不创建过滤切片或整段根编码缓存。读取时已完成 item 校验和规范化，哈希字段写入不再重复该步骤。
- Agent：保留原部署元数据、ManagedBalance 和 RuntimeState 的参与范围，直接将二进制字段写入哈希，不复制状态再转成 JSON。
- EVM：继续哈希现有确定性 `MarshalBinary()` 结果；ManagedBalance 已为紧凑二进制。保留原有格式标识 1，不新增 V2；哈希域统一为 `SATOSHINET:EVM_STATE_ROOT\x00`，不附加版本后缀。

三类根值均会因编码字节变化而改变，并传递到节点组合根。要求的是同一新版本内的 map 顺序确定性、状态往返、磁盘重启及跨节点验证一致；不要求与旧 JSON/V1 哈希值相等。所有字段仍按明确 schema 写入，未增加持久化状态或兼容机制。

## 运行边界

RPC/HTTP 的 JSON 格式和 Agent 的 LLM JSON 输入输出保留。包含旧 JSON 状态或余额的快照会明确解码失败；空数据库仍按原行为创建空状态。EVM 没有余额字段的快照可能与既有二进制格式字节相同，这不需要兼容分支。此次实现没有清理或重置任何现有节点数据目录。部署新版节点时，所有参与同一测试链的节点须使用相同版本，并由操作者安排相应测试链数据重建；不能混用旧状态快照和新版合约根。

## 前一阶段：持久化性能结果（三轮中位数）

测量时同机另一项目运行验证脚本和测试二进制，属于共享负载。执行前检查并等待可见的外部编译阶段结束；阶段前后进程快照不能完全排除期间短时外部编译或其他系统负载。三类测量组按顺序执行，节点插件及节点构建也串行。绝对耗时不能视为独占机器结果。

此前模板采用真实 `ApplyDefaultInvoke` 构造 0/20 个保留记录，再补齐指定数量 delegate；Autopay 默认充值记录会立即完成，原测量标签 `pending=20` 实际为保留的完成记录，表中的 20 应按保留记录解读。本轮根测量改用 `ApplyInvoke(cancel)` 生成真正未完成记录，并显式断言未完成数量；其余 delegate 的余额为 1000、累计支付为 0。Agent 为 ready 状态及指定数量的合法投注；EVM 为指定数量的账户，每个含代码、一个 storage 槽、余额和一种 ManagedBalance 资产。这些夹具用于本轮 JSON 与紧凑格式的等价对照，不与此前字段更丰富的 gob 诊断样本直接比较。
